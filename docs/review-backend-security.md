## Sprawdzone mechanizmy bez potrzeby przebudowy

- Hasła są hashowane BCrypt z kosztem 12; logowanie dla nieistniejącego konta wykonuje porównanie z hashem o tym samym koszcie. Zmiana emaila i hasła wymaga aktualnego hasła.
- Cookies uwierzytelnienia mają HttpOnly, konfigurowalne Secure i SameSite; połączenie SameSite=None z brakiem Secure blokuje start aplikacji.
- Refresh tokeny są losowe, w bazie przechowywany jest SHA-256, rotacja atomowo oznacza zużycie, a replay odwołuje rodzinę. Podpis, issuer, audience, typ i terminy JWT pozostają weryfikowane.
- Kontrola dostępu do projektów i zadań ukrywa niedostępne zasoby za 404; wyszukiwanie użytkowników wymaga wspólnego projektu albo własnego konta. DTO nie ujawniają hasha hasła.
- Zapytania korzystają z parametrów, a uploady otrzymują losowe nazwy UUID. Niedozwolone rozszerzenia, puste i zbyt duże pliki są odrzucane; limit konfiguracji wynosi 5 MB na plik i 10 MB na żądanie.
- Nagłówki CSP, nosniff, Frame-Options, Referrer-Policy, Permissions-Policy i HSTS dla HTTPS pozostają aktywne. Zaufanie do forwarded headers jest ograniczone konfiguracją zaufanych proxy.

## Zgodność wdrożeniowa i koszty

- Nowe JWT zawierają `sid`. Dotychczasowy JWT bez tego pola otrzyma 401; standardowe odświeżenie ważnym refresh tokenem wystawi token w nowym formacie. Migracja bazy nie jest potrzebna.
- Weryfikacja JWT wymaga jednego dodatkowego zapytania po istniejącym unikalnym indeksie `token_hash`. To świadomy koszt natychmiastowego odwoływania sesji.
- Limit 72 bajtów UTF-8 został uzgodniony z frontendem. Nazwy pól i publiczne adresy endpointów nie uległy zmianie; zmieniły się ograniczenia requestów opisane przez OpenAPI.
- Logout jednego urządzenia odwołuje jego rodzinę tokenów i zamyka aktualne streamy użytkownika w tym procesie. Inne ważne sesje mogą automatycznie wznowić SSE.

## Weryfikacja

Testy uruchomiono na Java 21, Maven i rzeczywistym PostgreSQL 16 przez Testcontainers/Colima. Zakres obejmuje testy jednostkowe, HTTP kontrolera plików, pełny łańcuch filtrów oraz testy integracyjne cyklu życia sesji i uploadów. Ostatni kompletny przebieg zakresu bezpieczeństwa zakończył się wynikiem **293 testy, 0 błędów, 0 porażek, 0 pominiętych — BUILD SUCCESS**. Po ostatniej poprawce blokad załączników i limitu 50 wykonano dodatkowo **33 testy, w tym 6 integracyjnych — 0 błędów, 0 porażek, 0 pominiętych, BUILD SUCCESS**. Obejmują one rzeczywistą konkurencję dwóch transakcji PostgreSQL. `git diff --check` nie wykazał błędów formatowania.

## Granice review i opcjonalny dalszy rozwój

- Limiter i rejestr SSE pozostają lokalne dla procesu. Wdrożenie wielu instancji wymaga wspólnego limitera oraz rozgłaszania odwołań SSE, np. przez broker. Obecny układ uruchomieniowy korzysta z jednej instancji backendu; nie dodawano nieużywanej infrastruktury.
- Walidacja nagłówków plików ogranicza podszywanie się pod typ. Nie zastępuje skanera antywirusowego ani pełnej walidacji dokumentów Office/PDF. Taki skaner wymaga wyboru usługi, polityki przechowywania i obsługi plików w kwarantannie.
- MFA, reset zapomnianego hasła i weryfikacja emaila są rozszerzeniami produktu wymagającymi określenia procesu i polityki dostarczania wiadomości; nie dodawano ich jako domniemanych błędów obecnych funkcji.
- Review nie zastępuje zewnętrznych testów penetracyjnych ani testu wydajności na docelowej infrastrukturze. Nie ujawniano plików środowiskowych ani rzeczywistych sekretów.
